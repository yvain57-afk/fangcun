# ADR-002：独立本机评估存储

状态：M2 采用；既有 SwiftData、Diary、练习、饮品及偏好存储不迁移、不清空。

## 选择与范围

采用 `InsightsStore` actor，位于 App 的 Application Support/FangcunInsights。M2 的对象是规范化健康样本、锚点、选源、睡眠段、版本化评估与删除审计；没有新增背景事件、跨端 outbox、提醒 ledger 或 Widget 文件，这些仍属于后续阶段。

与扩展旧 SwiftData schema 相比，独立 Codable 快照无需迁移用户旧记录。当前只缓存四类低频资料及 35 天原始样本，整份原子快照可审查、可注入故障。将来引入高频数据或较长历史时应重新测量规模，再决定数据库迁移，不能把当前方案视为无限容量方案。

## 文件及提交协议

- `insights-v1.json`：schemaVersion、校验和及 payload；样本、游标、来源、评估在同一个原子替换中发布。
- `insights-v1.previous.json`：上一次完整快照，作为损坏恢复入口。
- `deletions-v1.json`：优先提交的删除屏障，只保存 UUID tombstone 和 clear epoch。它不能提供数值、设备身份或健康结论。
- 每个目录由一个应用级 actor 独占；generation 比较防止迟到任务覆盖切源、删除和清除。M2 不支持两个进程共同写入此 store；Widget 不应打开业务库。
- iOS/watchOS 文件采用 completeFileProtectionUntilFirstUserAuthentication，目录 0700、文件 0600，并排除系统备份。不增加 App Group、HealthKit 或后台权限。

先提交删除屏障，再清理旧快照／备份，然后发布新快照。任何恢复都先应用屏障；初始化完成中断删除的磁盘清理。损坏 primary 可从 previous 恢复，但清空锚点、撤销当前资格并要求重新查询。删除 journal 损坏、未知 schema 或两份快照均坏时失败关闭，保留文件，不伪装空的健康状态。

明确清除递增 epoch，阻止在途旧事务；保留无数值 tombstone 防止旧样本重放。35 天限制针对原始样本，评估修订与最小删除标记不会按日默默清除。显式用户清除移除评估和旧审计，只保留删除屏障。

## 评估修订和重放

同周期相同输入保留 assessmentID/revision；语义输入改变生成递增 revision 和 supersedesID。输入摘要包括指标、样本标识、来源段、来源说明、基线、睡眠、配置和时区，不包括查询/计算刷新时钟。删除影响过的旧评估只留 ID、周期、revision、原因，不保留数值或来源摘要。

`ReadinessPipeline` 对并发刷新单飞；按类型最多读取 100 页、每页平台上限 500 项，单次没有无限循环。每次提交只推进已纳入事务的页面。失效锚点仅重试一次无锚点回读，清掉该指标旧缓存后重建，不能把上次未返回的值继续当当前输入。空读不推断授权拒绝。

## 实测依据与边界

`InsightsStoreTests` 覆盖提交前失败、发布后返回前失败、删除屏障后中断、主文件损坏、journal 损坏、未知 schema、分页删除、迟到修订、重复刷新、切源/清除与旧请求竞争、单飞和失效锚点回读。

故障实验使用真实临时文件和合成数据；故障点通过可控异常模拟进程中断。没有声称已经完成断电硬件实验、锁屏保护真机实验、系统后台交付或多设备同步。UI 与生命周期尚未接入新 service；M2 交付的是可调用、可持久化、可重放的数据链路，M3 之后才替换页面消费者。

# M1 决策记录

## M3-PRE

根据当前设计文档校正蓝色原生契约，仅浅色次级文字三通道各调暗一级，仍按原 4.5 门槛验证。显示偏好使用行为测试并保留重启 UI 核验；结束文案进入 catalog/CSV，以稳定标识及完整保存流程验收。详见 M3-PRE-CONTRACT.md。

1. **范围**：遵循交付包 START，本轮先 M0–M1。保留原生入口、版画猫狗、品牌色、练习/健康写入/饮品/设置；不启动全部重构。M2 golden fixtures 原样入库但未用新算法实现，不能声称准备度已上线。
2. **资格与结论正交**：新增 Core `BodyLoadDataAvailability`（insufficient / limited / buildingBaseline / available）。只有当前可靠、不同种类至少两类，且有 HRV 或静息心率，才能输出旧整体判断。不可用时保守返回旧 `buildingBaseline` level 保持旧调用兼容；新首页首先解释 availability，不能把它统一写成“基线积累中”。
3. **当前与历史分离**：历史天数只计算前 14 天且不含今天。M1 沿用原心血管 36 小时窗口；最近主睡眠也加 36 小时资格门控，超过窗口仍可展示原测量日期，但不参与当前判断。M2 再实现规范的主睡眠、24 小时准备度、来源一致性和置信度，不把旧阈值说成医学定论。
4. **失败优先**：provider 若将某种查询标为 unavailable，即使夹带旧数组也不能用于评估或冒充新读数。空结果不等于未授权，UI 不推断权限。
5. **时间**：`fetchedAt` 是查询，`computedAt` 是本次计算完成时的注入时钟；`measuredAt` 保留原始记录时间，聚合判断的 `assessmentMeasuredAt` 单独保留其最新样本时间。首页显示最近测量日期；详情展示查询、计算和每项测量。兼容只读 `lastUpdated` 仅给旧诊断调用，文案不称“同步”。
6. **运动保护**：暂保留旧 18 小时 / 45 分钟筛选，但保留 `workoutExcludedEvidenceIDs`。若过滤后本会落到 steady，则降低为 limited；原始偏离和训练背景继续展示。有独立未过滤偏离仍可保留 watch/elevated，不能因运动清空全部事实。
7. **观察不等于偏高**：新首页增加 watch 和 limited。至少两类合格证据、一项偏离为“轻度留意”；两项偏离才是“偏高”；不称心理压力诊断。身体线索卡的第二项换为实际 RHR/HRV，不再复制主状态作独立证据。
8. **旧快照**：缺失 `semanticsVersion` 的快照标为 legacy，原文字及旧短标题保留；新 M1 快照为 version 1。相同日期刷新不删除 legacy，旧记录不送入准备度。首次覆盖已有本机 archive 前保留 preM1 原始字节，坏数据保持不覆盖。完整 versioned storage 仍属 M3。
9. **测试边界**：12 组 DEBUG-only 原始 fixture 通过 provider→HomeViewModel→Core→FangcunDayState→SwiftUI；单元测试和 UI 测试的预期不放在 provider。原三状态视觉预览保留但限制 DEBUG，仅作视觉检查。Release 禁用 UI 测试入口。
10. **文案**：新增中文集中为稳定 key + String Catalog + COPY_REVIEW.csv。新增 UI 选择器使用稳定 accessibilityIdentifier，改文案不需要改算法、协议或选择器。

## M2-02：睡眠与基线边界

- 本地日期以主睡眠结束日归属，前 28 日期各取最长段；时区只影响日归属，不生成新的睡眠周期 ID。历史资料限定在当前主段开始之前，排除当前样本 UUID。
- 同段修订的 50% 重叠用两段跨度的较大值作为分母（任务书未指定分母）；存在多匹配一律待复核。
- 极端有限值的绝对边界在任务书中未给数值。最小补充为 HRV >10,000 ms 或 RHR >1,000 bpm 标记 extremeValue，不截断；集中工程配置、待校准，不能视为医学阈值。相对 HRV 高值仍严格执行第 4 章规则。
- 去重改为 UUID / 同源同步标识集合，只有显式跨源镜像策略才做区间对照。合成 20 日基线测试由约 13.65 秒降至 0.052 秒；模型和输出不变。

## M2-03: deterministic assessment

- Tests load the original G01-G10 JSON and generate raw sleep, SDNN, and RHR inputs. No copied expected-result table.
- A 1e-12 numerical tolerance handles log/exp round trips at exact severity boundaries; no model threshold changes.
- Availability, level, freshness, and sync state are orthogonal. Partial evidence remains visible without a level. A failed refresh preserves valid cached timestamps; invalidation and a newer sleep take precedence.
- Current sleep uses 48 hours; historical episodes use the bounded 35-day cache. Old malformed nights do not invalidate a separate current night. Training never hides observed deviations; drinks and completion counts are not scoring inputs.

## M2-04：存储与数据链路

采用 [ADR-002](ADR-002-insights-store.md) 的独立 Insights store。`ReadinessServices.make()` 提供 HealthKit adapter → ReadinessPipeline → 独立 store 入口，创建不申请权限或启动 observer。原首页、用户记录、练习及显示偏好继续使用原入口。

修订、输入摘要、配置版本、来源摘要、时间范围、资料质量和新鲜度随结果保存。规则参数进一步集中到 ReadinessConfiguration。删除优先于缓存，损坏恢复撤销当前资格；失效锚点重读时清理该项旧缓存。全部实现停在 M2，不接入 M3 页面、不做 M4 同步或 M5 通知。

## M2-R01：完整删除依赖

审阅成立。记录有界评估输入中 sleep/SDNN/RHR/mindful UUID 的保守依赖超集，包括基线睡眠、冲突、去重候选和被质量过滤的记录。它只用于失效，不参与指纹或模型参数。可能对未最终采用的候选多做一次失效/重算，避免漏撤销；不保存额外健康值。

新增可选 dependencyVersion；旧 schema 1 文件可读，缺少该字段的旧评估遇到删除一律保守撤销。新评估依赖已排除 tombstone，重算可以重新合格。删除、失败缓存和恢复都经过同一 redact 路径，不清库。

## M2-R02：分页发现与稳定选源分离

审阅成立。新增按指标持久化的可选 initialization（unread / inProgress / complete），与样本/游标同事务提交。仅完整读完首次发现才默认选源；失败或 100 页工作预算耗尽保留 inProgress 并续读。已选稳定来源和显式手动来源始终保留，失效锚点只重建读取进度，不自动切源。旧 schema 1 缺字段时可正常解码；已有来源继续权威，缺来源等待一次完整发现，不清库。

## M2-R03：有语义的单飞与一个待执行批次

审阅成立。比较配置、完整 Calendar/时区、排序后的练习区间与读取到的 store generation。同语义普通刷新共享在途任务；不同语义或 healthDataChanged 请求进入最多一个 pending 批次，串行补读。待执行设置被更新设置替换时明确返回 superseded，不冒充已经应用。多个同语义事件合并进同一个补读；补读期间的新事件可要求下一次有界读取，每个事件最多加入一个后续批次。没有自动失败重试循环；每轮仍有限页数。observer 接线将在 R05 使用 healthDataChanged 路径。

原 generation 提交校验保留，切源/删除/清除仍可拒绝旧结果。这里没有接入 App 生命周期或扩大后台权限。

## M2-R04：证据身份与刷新时刻分离

审阅成立。仅指纹投影使用固定逻辑 RHR 上界 sleepEnd+3h；真实抽取仍严格使用 min(now, sleepEnd+3h)，输出 feature.window 仍报告实际截止时间，未接受未来样本或改变门槛。新增可选 lastRefreshAttemptAt / lastSuccessfulRefreshAt 表示刷新尝试/成功检查时间；assessment.queriedAt 保留样本携带的证据读取时间。旧文件缺字段可解码为空，无迁移清库。

## M2-R05：完成处理之后确认 observer

审阅成立。SDK completion 由专用一次性锁保护适配器持有；处理任务使用 defer 在正常、读取错误、处理失败和取消收尾之后确认。Swift 6 SDK 的旧 block typedef 没有 Sendable 注解，无法直接标成 @Sendable 或 sending：仅这一外部回调适配器使用 @unchecked Sendable，所有私有可变状态由 NSLock 保护，取出置空后在锁外调用；没有关闭工程并发检查。

公开的 startObserving 接受 pipeline 和实时 context，事件强制走 healthDataChanged 的 pending 补刷新入口。保留最近 observer outcome；失败时 observerNeedsRefresh 为真。读取失败由 pipeline 存入评估，未提交的 cursor 不推进；存储失败不能伪称已经持久化。注册仍是显式调用，未接到 App 生命周期，未启用后台投递权限，未承诺系统唤醒。

2026-09-18 核对本机 HKObserverQuery.h 及 Apple [completion handler](https://developer.apple.com/documentation/healthkit/hkobserverquerycompletionhandler) / [observer queries](https://developer.apple.com/documentation/healthkit/executing-observer-queries)；确认是在处理资料完成后确认。官网普通页面依赖 JS，读取其官方 Markdown 版本核验正文。


### M2-R03 补充：失败缓存也需同一上下文

最终检查复现：练习排除区间改变后的睡眠查询失败仍返回旧 usual 缓存。新增可选 evidenceContextVersion（完整 Calendar 与排序的实际排除区间摘要），失败缓存仅在摘要已知且相同时复用。配置、来源、删除和新睡眠边界校验继续保留；不改模型参数。旧 schema 1 缺摘要仍可读取，不清库；遇读取失败时不将未知上下文缓存作为新请求结果。旧存储回归同时移除所有本轮可选新字段，核验兼容。

## 1. 本次要交付的产品

### 1.1 核心使用路径

用户在主睡眠后得到一份可解释的恢复参考；白天可以从 Watch、手机或组件进入短练习；需要活动时收到自己允许的提醒；练习与反馈留在本机，并在手机与手表之间可靠对齐。

### 2.2 M1 必须修复的回归

**资料不足门控。** 历史基线存在、近期查询失败或近期无样本时，旧引擎可以落入 `.steady`；新首页直接映射会显示平稳。为 `assess` 增加当前资料资格状态，至少要求两个不同种类的可靠当前证据，且其中有一项心血管指标，才允许旧整体状态显示“处于参考范围”。只有睡眠或只有一项体征时显示有限线索；完全无当前证据必须为空状态。[R4–R6]

**时间标签。** `fetchedAt` 仅表示查询；每项 `measuredAt` 表示测量；`computedAt` 表示计算；Watch 的 `receivedAt` 表示同步收到。不能用刷新或同步时间替代测量时间。

**观察与偏高。** 保留 `.watch` 与 `.elevated` 的语义区别，分别映射到轻度留意和身体负荷偏高。旧数据映射应明确 `legacy`，不要悄悄改写历史标题。

**运动窗口。** 原有近 18 小时、训练至少 45 分钟的规则会排除 HRV／静息心率偏离。新准备度模型不继承这种“屏蔽偏离”。运动作为解释背景保留；对仍使用旧判断的页面，至少展示训练保护状态而不声称各项体征正常。[R4]

**主观感受。** 新首页不强迫用户填写心情；已记录的疲劳或不适可以参与建议选择，但不能与 HRV 自动合成为“心理压力诊断”。旧推荐器中体征直接映射压力高低的路径不得原样接入。

**睡眠语义。** 没有最近主睡眠时不再把上一天睡眠显示为“昨晚”；采用带日期的“最近主睡眠”。固定旧快照保留原始语义，不能作为新准备度样本。

## 3. 数据层与设备能力分级

### 3.1 HealthKit 数据清单

| 类型 | 用途 | 优先级与回退 |
| --- | --- | --- |
| `heartRateVariabilitySDNN` | 主睡眠时段的 HRV 参考 | 核心；无可比数据则降低整体资料等级 |
| `restingHeartRate` | 系统静息心率与个人基线比较 | 核心；标为系统静息心率，不能改称夜间心率 |
| `sleepAnalysis` | 主睡眠识别、实际睡眠时长 | 核心；保留类别与来源，剔除单独 inBed 时间 |
| `workoutType` | 近期训练背景与重复训练识别 | 沿用；缺失不等于未运动 |
| `mindfulSession`／本机练习时段 | 排除干预中的 HRV，健康写入沿用既有规则 | 新增读取应独立说明；读不到时仍使用本机已知会话 |
| `respiratoryRate` | 后续增强的夜间背景证据 | M7 可选；本版不因缺失降低基础完整度，不进入主等级计算 |
| `stepCount`、`appleStandHour` | 活动背景和后续低活动提示 | M7 可选授权；不表示确切坐姿或系统提醒事件 |
| `heartRate` | 已有可选会话证据／后续静息片段研究 | 不作为本版全天实时监测入口 |

类型是否可用、实际可读与授权流程完成是不同状态。HealthKit 读取为空时，不把它命名为“用户拒绝了该项权限”；系统对读取授权提供隐私保护，开发时必须用本机 SDK 确认可判定的边界。[A1]

### 3.2 每条样本必须保留

`sampleUUID`、指标定义、单位、数值或类别、`startAt/endAt`、来源应用 bundle ID、`HKSourceRevision`、可用设备属性、采集口径、手工记录标记、可用元数据、查询时间、标准化版本。

内部生成 `sourceKey`，至少区分“指标定义＋来源应用＋设备标识可得部分＋采样口径”。没有足够设备身份信息时，记录 `sourceIdentityIncomplete`，不能猜测设备身份。无需索取设备序列号：来源应用＋可得 productType＋指标口径在已验证条件下足以建立稳定来源段时，可以继续评估；只有同源混入多设备且不可分辨、或口径确有歧义时才因此降级。来源名称仅用于展示，不能作为唯一主键。源版本改变保留记录；已知口径不兼容时建立新基线段。

**不允许只用 `isAppleWatch` 真／假来匹配所有非苹果来源。** 不同戒指、手环与手工数据可能都落在 false。SDNN 与 RMSSD 的统计定义也不同，不能因为单位都是 ms 就混合。[R4–R6]

### 3.3 选源与去重

先按样本 UUID 去重；同源同步标识／版本用于处理替换；不同应用镜像记录按指标、时段和来源策略处理，不能把数值相同一概当成重复。

每个指标选择一个主来源，不同指标可以选择不同来源。优先沿用已有可用且可比较的来源，其次尊重用户指定；首次使用可选择历史有效日覆盖最充分的来源，同等条件优先设备原始记录。不能仅因新出现一个 Watch 样本就把已有稳定戒指基线切换过去。

用户手动切源：保留原评估，建立新基线段，用已有该源历史回填基线；不把旧源均值沿用。主源暂缺数据：先显示缺失，不无声切到备用源。用户同意或明确的已验证替代策略才允许切换，并展示变化。

睡眠跨源不相加。选定主睡眠源后，在该来源内部做区间并集。训练按原始活动类型、时间重叠与来源处理镜像；保留原 activity type，不只比较翻译后的“训练”文本。

### 3.4 能力状态

`DeviceCapabilityProfile` 由实际数据形成，不能根据品牌白名单推断完整支持：

- **完整资料**：主睡眠、可靠当前 HRV、可靠当前静息心率，且两项体征基线均成熟。
- **初步参考**：当前三项可用，两项体征基线均达到初步门槛，但至少一项未成熟。
- **有限资料**：只有部分关键指标、样本数量不足、来源口径确有歧义或睡眠待复核。仅展示可用项及限制，不给总等级。
- **资料不足／待同步**：没有合格当前输入或没有可识别主睡眠。练习、记录、活动提醒继续可用。

Oura、Garmin、华为等具体品牌兼容性不写死在宣传或评估代码。建立 `device-compatibility.md`，只登记真机核对到的型号、系统／配套 App 版本、导出类型、到达延迟与结果。未测试品牌不等于不兼容，也不等于已完整支持。

### 3.5 查询与后台

首次只读初始化回看 35 天，为 28 天基线和跨边界睡眠保留余量。日常以锚点增量处理新增和删除，必要时重算受影响窗口；查询锚点只在本地事务成功后推进。

`HKObserverQuery`／后台交付用于“有机会时获取新资料”，不得作为每分钟运行或确定唤醒的保证。启动时注册一次，完成回调及时确认；锁屏保护、系统限流、低电量、应用强退等进入正常回退路径。[A2]

解锁／回前台、手动刷新、授权流程结束、相关健康样本变更时触发合并刷新。采用单飞与请求版本保护，避免旧请求覆盖新结果。不能每次画组件都重新扫描 35 天健康资料。

## 4. 准备度模型 v1：先把参考规则做成确定的工程

### 4.1 本模型的地位

以下阈值是**用于实现、测试与小范围校准的可解释启发式参数**，未被验证为医疗阈值或竞技训练指标。它们必须集中在 `ReadinessConfiguration`，随 `algorithmVersion` 保存。

本版不生成 0–100 分。对外使用“恢复参考（试用）”的语义；正式发布前完成第 15 章的试用门槛。Codex 不得自行写“医学级”“精准测压”“准确识别透支”等效果承诺。

### 4.2 主睡眠与恢复周期

1. 从最近 48 小时睡眠样本识别候选段，同一主源只计算实际 asleep 类别的区间并集。清醒间隔不计入时长。
2. 同源相邻睡眠区间间隔不超过 90 分钟时可合并为一个 episode；这是初版分段参数，须测试夜间长清醒、分段睡眠及午睡。
3. 候选需已结束、实际睡眠至少 2 小时、结束距计算时刻不超过 24 小时。多候选时以实际睡眠最长者作为初选，时长相同选结束较晚者。没有合格候选则不硬判准备度。
4. 超过 14 小时、明显重复冲突、未来时段、严重来源混杂列为 `needsReview`，不把它当作正常长睡眠。短于 2 小时作为短睡记录，用户可人工选为主睡眠后重新评估，但必须保留人工选择标记及有限参考状态。
5. 允许“选择本次主睡眠”，处理轮班、拆分睡眠。不要把凌晨固定时间当作唯一合法睡眠时段。
6. 两个至少 4 小时的候选段均在 24 小时窗口内、且结束时间相隔超过 6 小时时，视为主段选择可能有歧义，提供选择入口并暂不发晨间摘要；不要把单纯“最长”包装为确定识别。
7. 每个识别段获得持久化 `sleepEpisodeID`；样本晚到导致范围调整时，如同源且区间重叠超过 50%、结束时间差不超过 3 小时，优先作为同段修订。多段匹配冲突时标记待复核，禁止任意合并。
8. `recoveryCycleID` 与选定主睡眠关联，不能只使用当前公历日期。展示可称“今日”，数据应保留时区、主睡眠结束时间和明确评估周期。

### 4.3 当前 HRV 与静息心率

**HRV：** 仅使用选定主睡眠 asleep 区间内、同一主源、SDNN 口径的正有限值；与已知练习／正念时段及前后 30 分钟重叠的样本不进入准备度。过滤无效记录不等于删除用户健康记录。

睡眠中至少 3 个有效 HRV 样本，且覆盖至少 2 个不同小时桶，才算本版可靠 HRV。小时桶按绝对时间划分，避免夏令时重复小时问题。1–2 个样本可展示但为有限资料。不要从稀疏样本插值出整晚连续 HRV。

对每个有效值取自然对数后求中位数；保存原始 ms 中位数用于展示，对数空间用于偏离计算。

**静息心率：** 使用选定主源在 `[sleepEnd−24h, min(now, sleepEnd＋3h)]` 中最新的可靠系统静息心率样本。不能把常规心率样本直接改名为静息心率。若仅有这一路径无法获得有效样本，保留有限资料，不临时发明替代。

若同一样本被前一恢复周期使用，不作为当前周期的“新”静息心率证据；可展示为旧数据。历史回算采取相同取样规则。详情明确静息心率的实际测量时间，其测量窗口未必等于整晚。

### 4.4 个人基线

窗口取当前主睡眠之前的 28 个本地日期；历史分段按与当前相同的源、指标定义、采样条件与抽取方法计算。每个日期最多一个主睡眠样本，先选该日睡眠最长段。当前 episode、当前使用的样本 UUID 及任何未来资料不得进入基线。

分别保存 HRV 与静息心率有效基线日数：0–6 日为建立中；7–13 日为初步；14–28 日为成熟。不能以两项日数的最大值代替每项资格。用户首次授权可直接利用真实历史，不强迫从安装当天重新等待。

HRV 基线：历史每晚 log 值中位数的中位数 `M_h`；尺度 `S_h=max(1.4826×MAD, 0.10)`。

静息心率基线：历史有效日静息心率的中位数 `M_r`；尺度 `S_r=max(1.4826×MAD, 3 bpm)`。

`MAD=median(abs(x−median(x)))`。两个尺度下限用于防止基线几乎恒定时除以零或极小数放大噪声；它们是待校准参数。极端但有限值先标记异常质控，不简单截断为正常值。源不明、手工录入或口径不兼容时不可伪装成熟基线。

### 4.5 初版确定性计算

定义不利方向的偏离：

```text
hrvDeviation = (M_h − currentLogHRV) / S_h
rhrDeviation = (currentRHR − M_r) / S_r
metricSeverity(d): d < 1 → 0; 1 ≤ d < 2 → 1; d ≥ 2 → 2
```

若 HRV 明显向高侧偏离（`currentLogHRV > M_h＋2×S_h`），不奖励“超常恢复”；记录 `hrvAtypicallyHigh`，整体资格降为有限资料，解释为需要更多线索。其他数值／来源异常也走质控通道，不用良好等级掩盖。

**自主神经相关维度 A：** 两项体征均可靠时，任一 severity=2，或两项都为 1，则 A=2；仅一项为 1 时 A=1；均为 0 时 A=0。这避免把 HRV 和静息心率当成两种完全独立的健康证明。

**睡眠维度 S：** 目标睡眠默认 8 小时，允许用户调整并标注为个人目标。初版设置范围 7–10 小时。这是成人产品的默认交互范围，不能据此推断个人医学睡眠需求；不把调低目标宣传为优化恢复。以 `deficit=max(0,target−actualAsleep)`，不足 60 分钟为 S=0，至少 60 且不足 120 分钟为 S=1，至少 120 分钟为 S=2。目标与阈值仅构成软件参考，不能抵消疾病、轮班或个体需要。

**总体等级，只有资料合格时计算：**

| 条件 | `ReadinessLevel` | 展示语义 |
| --- | --- | --- |
| A=0 且 S=0 | `usual` | 选用指标接近个人参考 |
| A≥1 或 S≥1，且未达下一条件 | `reduced` | 部分恢复线索低于平常／目标 |
| A=2 且 S≥1，或 S=2 且 A≥1 | `low` | 多维恢复线索需要留意 |

单项严重偏离不能直接宣称整体低准备度，更不能诊断原因。两项体征均初步以上但存在未成熟基线，可生成 `provisional` 参考并显著标注；禁止据此发送身体状态异常通知。关键项缺失或质控不通过时 `level=null`，仅返回分项证据。

**酒精、咖啡因、糖饮、主观疲劳、活动时长和完成练习次数不直接进入上述加扣分。** 它们进入背景与建议层。近期训练不屏蔽 HRV／静息心率偏离，也不重复计算成额外惩罚。

### 4.6 状态与新鲜度，分别存储

使用正交状态，禁止一个 enum 同时承载数据质量、身体状态与刷新动画：

- `availability`: `assessable / provisional / limited / insufficient / awaitingData / failed`。
- `level`: `usual / reduced / low` 或空。
- `freshness`: `current / historical / stale`，由时钟与评估周期计算。
- `syncState`: `local / queued / received / disconnected`，仅反映端间同步。
- `isRefreshing`: 页面过程状态；刷新中可保留已有合格参考及其原时间。

评估锚定一次主睡眠。从该周期主睡眠结束起 18 小时以内、且没有新的主睡眠替代时可以作为当前周期参考；18–24 小时保留为上一时段参考；超过 24 小时从主状态区域回退到待更新。这个有效期是产品参数，不等同生理有效性期限。

页面显示“基于 09月18日 07:20 结束的睡眠”等明确锚点。再次刷新、重算或同步不得延长锚点有效期。详情允许看历史，Widget 在到期时间预置中性 timeline entry。

### 4.7 晚到资料、修订与冻结

距最新候选 asleep 片段结束不足 30 分钟时为资料到达缓冲，不发晨间通知；仍可展示分项。30 分钟是工程等待参数，片段结束不证明用户已醒，不能使用“已检测到起床”的措辞。候选段持续补齐时重新检查稳定性。达到完整资格后可形成版本 1；睡眠阶段补齐、静息心率晚到或源记录删除时生成版本 2，并记录 `supersedesID` 与修订原因。

同一周期通知最多一次，修订不重新推送。不得因为晚到数据就把晨间记录覆盖成日间状态。基础输入或数据源被用户删除后，重算并撤销不再有效的当前资格，不能永久保留“已验证正常”。历史保留最小审计信息，并服从用户删除要求。

### 4.8 资格判定顺序

先处理输入读取失败且无有效缓存的 failed；再处理候选睡眠仍在等待资料的 awaitingData；没有合格主段或任何有效当前体征时为 insufficient。存在局部证据但关键项缺失、质量不合格或任一体征基线不足 7 日时为 limited，level 为空。当前三项均合格且两项基线均至少 7 日、至少一项不足 14 日时为 provisional；均至少 14 日时为 assessable。最后独立计算 freshness，不因历史有合格等级就继续把它当当前值。

有有效缓存时，查询失败可保留缓存原时间和等级，同时显示刷新失败；不能把缓存重新签成新鲜数据。数据源删除、用户清除数据与无效化命令优先于缓存保留。

### 4.9 必须先实现的纯函数接口

```text
SleepEpisodeBuilder.build(samples, sourcePolicy, calendar)
BaselineBuilder.build(episodes, metricPolicy, beforeEpisode)
EvidenceQualityEvaluator.evaluate(input)
ReadinessEngine.evaluate(input, configuration) -> ReadinessAssessment
AssessmentFreshness.resolve(assessment, clock) -> Freshness
RecommendationEngine.recommend(assessment, context, constraints, feedback)
NotificationPolicy.decide(candidate, preferences, ledger, clock)
```

Core 不依赖 SwiftUI、HealthKit、WatchConnectivity 或文案字符串。注入 Clock、Calendar、时区与配置；相同输入和配置必须得到相同输出。平台仓库负责把 HealthKit 类型转换为领域类型。

## 5. 数据模型、存储与迁移

### 5.1 统一评估对象

所有页面、组件和通知消费同一评估结果；平台端不得再写另一套恢复计算。最低字段如下，类型名可按现有代码规范调整，语义不可删减。

| 对象 | 最低字段 |
| --- | --- |
| `ReadinessAssessment` | `assessmentID`、`recoveryCycleID`、`revision`、`supersedesID`、`algorithmVersion`、`configurationVersion`、`featureSchemaVersion`、`inputFingerprint` |
| 时间与范围 | `sleepEpisodeID`、`sleepStartAt`、`sleepEndAt`、`evidenceWindowStart/End`、`computedAt`、`latestMeasuredAt`、`validUntil`、`timeZoneID` |
| 判断 | `availability`、可空 `level`、`evidence[]`、`missingReasons[]`、`qualityFlags[]`、每项基线日数、主源摘要、是否人工选主睡眠 |
| `MetricEvidence` | 指标定义、值和单位、当前统计值、基线中心／尺度、测量窗口、样本数、主源 key、偏离程度、资格、原因 code |
| `RecoveryContextEvent` | 事件 ID、类型、发生时间、录入时间、关联周期、来源、可选数值／用户反馈；不用于悄悄覆盖评估 |
| `PracticeEvent` | 稳定 session ID、起止时间、目标／实际有效时长、协议版本、状态、结束原因、源设备、写健康归属、会话质量 |
| `PracticeFeedback` | 反馈 ID、session ID、可选帮助程度、可选前后自评、不适标记、发生与修改时间、来源设备 |
| `ReminderPlan / DeliveryLedger` | 计划 ID、事件去重 key、所有者设备、计划／有效时间、类型、状态、通知请求 ID、用户动作、版本 |
| `SyncEnvelope` | 协议版本、设备安装 epoch、消息 ID、实体 ID、修订号、事件类型、创建时间、payload、可选删除 tombstone |

整体摘要不得仅保存一段中文。原因 code 例如 `sleepBelowTarget`、`hrvBelowBaseline`、`rhrAboveBaseline`、`baselineBuilding`、`currentDataMissing`、`sourceChanged`、`dataStale`，经文案层转为用户可见文字。

### 5.2 存储默认方案

保留原有 SwiftData container 与记录类型。新评估、背景事件、跨端 outbox、提醒 ledger 使用独立的本机 Insights store 或现有容器的正式版本化 schema；以迁移风险较低的方案为准，Codex 需在 ADR-002 写出选择与实测依据。不能通过清空旧库解决 schema 错误。

iPhone 向其 Widget Extension 提供**最小化摘要文件**，通过同设备 App Group 共享；Watch 收到同步后写入 Watch 本机摘要，再由 Watch 自己的 App Group 分享给其组件。**App Group 不能在 iPhone 与 Watch 之间共享同一个磁盘文件。** 跨物理设备走 WatchConnectivity。[A3]

摘要采用 Codable、schemaVersion、原子替换写入。读失败返回中性状态，不能返回上一次 Preview。大小以几 KB 为目标，不携带健康原始样本或完整情绪记录。Widget 只读摘要，不直接修改业务数据库。

### 5.3 饮品与历史迁移

原 `fangcun.native.diary.v1` 存档先完整备份到本机受保护位置，验证解码、条数与校验摘要，再导入 v2。迁移幂等，记录迁移版本；损坏存档保留原始字节与可理解提示，不能用空数组覆盖。[R6]

新增饮品字段：`consumedAt`、`recordedAt`、`volumeML`、`caffeineMG`、`alcoholGrams`、含糖份数／可选已知糖量、`estimateMethod`、`estimateVersion`。原记录的 date 迁为 `consumedAt`，记录“由旧版本迁入”；旧时间不明的字段保持空。

允许手机补记过去 7 天的饮品、修改时间和容量、撤销。不能把没填的酒精或糖克数设为实测零；旧版本已经明确的固定估值保留估值属性。用户以后修改默认杯量，不重算旧杯量。

旧每天文本快照标记 `legacyDailySnapshot`。可继续查阅，不能转为伪造 HRV、睡眠样本或新准备度等级。新恢复评估不补造安装前完整历史；可以回溯真实健康输入建立基线，若提供历史重算则必须显示“回溯估算”和模型版本，本版默认不展示这项入口。

### 5.4 删除、导出与隐私

默认将原始健康数据留在 HealthKit，应用只保存计算必需的特征、时间与最小来源信息；短期查询缓存按有界窗口清理。用户可以删除本地评估、练习、反馈或全部本地资料，并单独选择是否删除本应用写入的健康记录。禁止删除其他来源。

删除在两个设备通过 tombstone 同步，旧 outbox 重放不能复活记录。离线设备收到删除前无法即时清理，应在设置中说明“待另一设备同步”。“停止读取”也要停止观察器、清除外部摘要并发送隐私重置消息；用户仅在系统中撤销读取时，应用可能无法准确得知，缓存必须依靠时效自然失效。

导出只在用户主动触发后生成本地文件并打开系统分享。测试日志、Git、截图、诊断导出默认不含健康原始值、设备标识、情绪自由文本或签名信息。允许用户在明确说明后单独导出供排障的去标识数据，不自动上传。

## 6. iPhone 页面增量设计

### 6.1 今日页：原布局内完成升级

保留页头、品牌与显示切换、主状态卡、5 分钟呼吸主按钮、身体线索卡、饮品入口、趋势入口和可选感受入口的整体顺序。[R6]

**主状态卡**切换到 `ReadinessAssessment`：状态标题、最多两行解释、资料成熟度／当前有效性、主睡眠日期时间、原有猫狗情境。不新增巨型分数，不另建重复的“压力”和“恢复”双结论。有限资料与等待状态仍能直接开始练习。

**身体线索卡**显示睡眠、HRV、静息心率中的可用摘要，允许保持原有双列＋下一层详情。不能用由主状态复制出的“身体恢复”充当第二条独立证据。

**当下建议**作为既有练习入口下的一条紧凑次级行，最多推荐一项。用户不操作时保持现有首页 5 分钟入口；选择“只有一分钟”“不便站起”“想休息”可以改变次级建议，不强迫问卷。

**活动提醒入口**放在次级操作或设置，开启后只显示当前计划与下次时间。没有启用时不长期占据首页主卡。

### 6.2 准备度详情

详情顺序：整体参考与有效范围、三项证据、与个人基线的比较、缺失／质控说明、近期训练与饮品背景、数据来源、规则说明。

每项体征显示当前值、统计口径、来源、测量时间、基线有效日数与参考范围。图表可沿用现有配色和卡片；高 HRV 不自动渲染成“更好”。睡眠是实际 asleep 时长，同时显示个人目标，不能把卧床时长计为睡眠。

未提供数据的项可解释检查路径，但不准确声称已拒绝授权。支持重新请求授权、选择主来源、选择主睡眠和手动刷新。选择更改后说明重新建立比较条件。

### 6.3 历史与趋势

保留原入口，增加 7／28 天切换。主视图用等尺寸状态标记：完整等级、初步、有限、缺失、历史旧记录各自有文字与可访问标签。空白日期仍为空白。

选中一天后列出该天恢复周期及修订、睡眠、训练背景、饮品事件、两端练习和反馈。多次恢复周期不能互相覆盖；主视图按最后一个主周期展示并提示还有其他记录。

练习反馈统计只写“在 N 次有反馈的练习中，M 次选择有帮助”；无反馈不当作无效或有效。至少同类 5 次显式反馈才展示偏好摘要，少于 5 次展示单次记录。5 次是界面显示门槛，不能据此宣称统计学显著。

### 6.4 设置增量

新增分组：准备度与来源、手表连接、提醒与安静时段、组件隐私、恢复偏好、本机资料管理。既有显示、音频、健康连接与调试入口保留。推荐偏好、提醒类型与健康授权分别控制，不合并成一个“大同意”。

## 7. Apple Watch：完整的腕上产品

### 7.1 导航与状态卡

Watch 首屏使用原品牌资产和语义色的腕上适配版本。保留原生深色背景、系统字体与大触控区；以 iPhone 当前设计为主，不延续旧 mint 作为另一个品牌。无需移植手机整张纸纹、大阴影或持续 Metal 动画。[R2、R7]

首屏自上而下：恢复摘要、主睡眠／评估时段、一项主要依据、常用短练习大按钮。向下滚动可见轻记录与今日练习。情绪罗盘、每日一句、更多练习、同步诊断收至次级入口，不删除旧功能或旧记录。

从表盘快捷练习入口：一次点击打开对应 Watch 路由，第二次明确点击开始。初次安全说明允许增加一步，不能作为每次重复问卷。常用时长与触感偏好在本机记住，不要求每次选择。

首屏状态必须覆盖：完整资料、初步参考、有限资料、等待手机初次设置、正在同步、断连但摘要有效、摘要过期、本机数据损坏。断连本身不把有效摘要清空，也不延长有效期。

### 7.2 本版 Watch 场景

| 场景 | 可执行要求 |
| --- | --- |
| 抬腕了解状态 | 默认一屏可读核心结论，不需先读每日一句；详细原因最多再进入一层 |
| 常用短练习 | 默认现有 60 秒双吸一呼，用户可设为已有 3 分钟节律呼吸等有效协议 |
| 活动间歇 | 进入 2 分钟轻活动或 60 秒坐姿活动选项，先允许判断环境是否安全 |
| 快速饮品 | 白水 250 ml、美式 300 ml 等沿用现有默认估值；一次确认保存，提供短暂撤销入口 |
| 可选反馈 | 一屏显示有帮助／没明显变化／不舒服，允许直接完成跳过 |
| 离线使用 | 手机不可达仍可启动已安装练习、保存事件与反馈；连接恢复后去重同步 |

饮品只有用户明确选择后才记录。Watch 的“已记下”以本机持久化成功为前提；“已同步手机”必须等待手机确认，不可在排队后立即显示。

### 7.3 独立会话控制器

新增 `WatchPracticeSessionController`，由 Watch App 级对象持有；View 仅展示状态与发送动作。会话至少具有：

```text
idle → preparing → running ↔ paused → finishing → completed
                  ↘ interrupted       ↘ saveFailed → retry
                  ↘ cancelled
```

`sessionID` 在用户开始时生成并持久化。时长、呼吸相位、触感、音频如有，均从同一个权威时钟计算。`TimelineView` 用于绘制，不能当唯一会话驱动；不能把呼吸写成另一段与 iPhone 不同的取余节拍。[R7]

进程内使用单调时钟计算有效经过时间，避免手动改系统时间造成跳变；持久化累计有效时长、最近检查点、墙钟时间和状态。重启后不能把未知的后台空档自动计为已完成练习，进入中断恢复，允许保存已知时长或重新开始。

暂停冻结练习时钟和触感，但不会宣称获得无限后台运行额度。结束后不得再发迟到触感；取消异步准备后不得重新启用音频或训练会话。连续点结束／重试必须只产生一条会话记录。

### 7.4 垂腕、触感与后台：必须先做能力验证

真实的正念／呼吸练习可评估 `WKExtendedRuntimeSession` 适用模式，先在当前 Xcode 的 SDK 文档确认配置、允许类型、时限及 delegate 回调，再进行垂腕真机验证。延长运行只覆盖主动练习，不能用于全天久坐计时或普通后台轮询。[A4]

触感使用平台已有类型，默认开、可关闭；不能承诺任意波形、持续震动或每个系统状态下完全一致。若采用区分吸／呼的触感，先用短说明与试触感帮助用户识别，禁止通过补发积压节拍“赶进度”。

系统回收扩展会话、转入其他 App、来电、强退或低电量影响运行时，保存检查点并进入可解释回退。声音和触感不可用，视觉练习仍可用；不得偷偷开启 HKWorkoutSession 来规避限制。

**现有可选心率证据模式：** `LiveHeartRateSession` 会以 `.mindAndBody` 创建训练会话并最终丢弃记录。[R8] 本版默认关闭该模式，保留代码与记录兼容；将其能力、资源清理、训练并发影响和商店说明列为单独验证门。普通呼吸、NSDR、活动提醒不依赖它。只有真实用途、用户明确选择与验证通过后，才恢复入口。

### 7.5 结束、保存与反馈

先将练习事实本地提交，再处理 HealthKit 写入与手机同步；健康写入失败不能丢失练习。结束按钮允许安全提前结束；有效时长不足完整协议时保存为提前结束，不写“完成全部”。0 秒误触可直接丢弃，但保留防重复状态。

反馈与完成为不同实体。用户跳过不生成虚假的中性／积极情绪；反馈不自动写成 HealthKit State of Mind，只有现有明确的主观记录流程才能写该类型。

选择“不舒服”后停止当前引导，展示简短安全出口，降低相同练习的自动推荐优先级。不要根据单次反馈判断用户疾病或训练禁忌。

### 7.6 真机验收目标

同一真实设备至少验证：常亮与非持续亮屏、垂腕 60 秒和完整 3 分钟、暂停 30 秒后继续、来电／切换 App、飞行模式、手机关蓝牙、系统结束会话、退出后再次打开、连续多次保存、低电量模式。

每条记录设备型号、系统、场景、实际有效时长、丢失／重复触感、CPU／能耗观察和结果。不在模拟器上宣布触感、后台或耗电通过。普通试用 24 小时与原版对照，目标无无意义后台循环；电量增量先记录，内部预警可暂设同条件超过 5 个百分点需调查，不能作为公开续航承诺。

## 8. 跨端同步与一致性

### 8.1 数据权属

| 数据 | 权威写入者 | 同步方式 |
| --- | --- | --- |
| 恢复评估 | iPhone | 最新摘要通过 `updateApplicationContext`，有界历史按需同步 |
| Watch 练习／反馈／饮品 | 创建事件的 Watch | 持久化 outbox＋`transferUserInfo`；可达时即时消息加速 |
| iPhone 练习／饮品 | iPhone | 手机本地权威；需要腕上摘要时同步最小结果 |
| 提醒偏好 | iPhone 配置主端；Watch 可提出变更命令 | 实体 revision＋确认；紧急“今天静音”先在本机生效 |
| 练习实时状态 | 发起设备 | v1 不跨端抢占控制，其他端只显示已知状态及时间 |
| 删除 | 用户操作端发起明确命令 | tombstone＋持久化确认，防止旧数据复活 |

`updateApplicationContext` 只用于可被新状态替换的摘要，不用于不能丢的完成事件。`sendMessage` 失败需回退持久化队列，不能假设 `isReachable=false` 就表示设备未配对。[A3]

### 8.2 幂等与重试

每条事件固定 `eventID`、`entityID`、`revision` 和 `originInstallationID`。接收端在单一数据库事务中去重、应用、记录已接收；成功持久化后才回 ACK。收到重复事件回相同确认，不再次写入。

Watch outbox 保存到收到 ACK 后才释放。系统“已经安排传输”不等于手机已经应用。消息可重复、延迟、乱序；较低修订不能覆盖高修订。实体编辑与删除使用修订＋tombstone，不只比较系统时间。

本机主动重试采用有上限退避，不做后台轮询循环。源设备重装用新的 installation epoch；配对切换后清理旧配对摘要，不能让前一只手表的数据重新成为当前状态。协议版本过高时保存可诊断错误并保留本地事件，不强行解码成空对象。

### 8.3 HealthKit 写入只由一端负责

新练习由源设备写 HealthKit；另一端仅导入应用记录，不再向 HealthKit 写同一练习。源端写失败留其原队列重试，不能未经协议让另一端接管，否则不同 source 可能形成重复健康样本。

沿用项目已有 syncIdentifier／sessionID 元数据。手机同时从 HealthKit 和 WatchConnectivity 读到同一会话时，按 session ID 合并应用记录。不要假设跨来源相同 `HKMetadataKeySyncIdentifier` 自动形成全局唯一记录。

旧 Watch 记录只能恢复已经存在的事实；无法找到稳定 ID 时用明确 legacy 标记和保守时间匹配，冲突交给用户复核，不补造反馈。

### 8.4 离线边界

Watch 可以离线完成基础练习；手机不在附近时未必能计算新准备度。跨端“今天静音”在断连时可能暂时无法影响另一端，UI 要显示待同步。本版不承诺离线跨设备瞬时一致性，也不为此引入服务器。

## 9. 恢复建议与轻量行动

### 9.1 建议引擎的职责

新增纯函数 `RecoveryRecommendationEngine`。输入包含可用的恢复评估、用户主动选择的目标、可用时长、坐姿／可走动条件、常用练习、近期明确不适反馈；输出包含 `actionID`、`reasonCodes`、时长、准备条件和安全提示 key。

用户不提供目标时，采用常用短练习或中性选择，不通过 HRV 推断他正在焦虑、工作受挫或人际关系紧张。身体状态与主观报告冲突时分别显示，两者都不能覆盖另一方记录。

| 输入场景 | 默认建议 | 必须保留的选择 |
| --- | --- | --- |
| 数据不足，用户只想休息片刻 | 常用短练习或 2 分钟安静休息 | 不连接健康也能开始；不追问心情 |
| 恢复偏低＋用户表示疲倦 | 2 分钟安静休息；时间与场景允许时进入既有 NSDR | 可以不练习，仅调整当天安排 |
| 用户明确想平静一下，适合静坐 | 已有双吸一呼或节律呼吸 | 更换练习；不要憋气或强迫加深呼吸 |
| 用户主动开启的工作间歇到时 | 2 分钟轻活动 | 座位内舒展替代；稍后；今天静音 |
| 状态接近平常 | 保留常用入口 | 不自动建议加大运动量 |
| 某练习曾明确反馈不适 | 停止主动推荐该练习 | 用户自行查看时再次显示准备与退出提示 |

一屏最多一个推荐和一个更换入口。选择不应形成长问卷。不适过滤优先于偏好排序；默认不建立“用户身体适应能力”之类未经验证的标签。

### 9.2 新增行动的最小范围

使用独立 `RecoveryActionKind` 包装已有 `PracticeKind` 与新活动，避免直接改变旧 Codable 枚举导致历史记录解码失败。新增三个轻量协议，全部需要内容版本、准备条件、阶段与安全提示。

| ID | 默认时长 | 交互与内容边界 | 写入规则 |
| --- | --- | --- | --- |
| `movementBreak` | 120 秒 | 先确认环境安全；轻松走动或按能力改变姿势，保持自然呼吸；不强制步数 | 只存方寸活动记录，不写虚构训练、热量或正念时长 |
| `seatedReset` | 60 秒 | 座位内轻柔调整姿势，肩部与手腕在舒适范围内活动；不做强迫颈部旋转或疼痛拉伸 | 只存方寸活动记录；不根据完成次数计算恢复加分 |
| `quietRest` | 120 秒 | 安全坐姿下安静停留，可睁眼；无强制呼吸节拍 | 初版只存本地休息记录；不自动等同冥想或睡眠 |

文字、阶段时长和插图均使用现有设计组件。缺少合适动作图时使用清晰的阶段文字和现有静态角色，不生成新的角色姿势替代已确认原画。内容初稿可开发运行，但发布前须人工检查运动安全和措辞。

走动过程中不要求持续看屏、闭眼、跟随双吸一呼，也不以强烈震动催促动作。轮椅用户或不能站立者可选座位版本；不把站起来作为所有人的必做目标。

### 9.3 反馈模型

`RecoveryFeedback` 采用可选 `helpfulness = helpful / unchanged / uncomfortable`，另有 `skipped` 状态。没有回答用 null，不能默认 helpful。可选文字备注仅保存在本机。

同一次行动只能有一份当前反馈，可编辑且保留 revision。反馈不改变当天准备度。近 5 次以上的真实回答可以显示回答分布与次数；这个门槛只是展示条件，不能据此宣称疗效。未回答的记录不进入“有帮助比例”分母。

新增行动与现有练习统一保存 `sessionID`、`actionID`、协议版本、计划／实际有效时长、结束原因、来源设备及反馈；不同活动的意义保持独立。

### 9.4 安全与自主选择

首次开始相应行动时说明适用环境、保持舒适、不适即停；后续使用保留可见退出和准备说明入口。用户主动表示正在驾驶或不方便时，不开始视觉／呼吸／动作引导。没有相关数据时不要声称已经检测到驾驶。

遇到用户明确报告严重或持续不适，展示停止练习并寻求适当帮助的通用提示，不给出诊断，也不声称低准备度能够排除或确认疾病。内容安全审查属于发布门槛，不因文案以后会重写而省略。

## 10. 久坐相关功能：采用自主活动提醒

### 10.1 平台结论与命名

苹果的站立提醒主要属于 Apple Watch 健身记录体验。本次公开文档核对没有找到可供方寸订阅“苹果刚发出站立提醒”的公开事件接口。本次不做读取、拦截或追加其他应用通知，也不通过私有 URL 或模拟点击改变系统设置。[A7–A9]

HealthKit 的 `appleStandHour` 是小时级站立活动类别；它不等于连续坐姿时长，也不等于苹果站立通知的发送事件。手机静止也可能只是手机留在桌面。因此，本版名称使用“活动间歇提醒”或“工作间歇”，不宣传精确久坐识别。[A9–A10]

**本版可交付路径：用户允许方寸设置自己的定时提醒；到时在同一条通知中给出一条建议，并可进入轻活动。** 不在苹果的通知之后再补发一条。

### 10.2 MVP：用户主动开始的一次间歇计时

手机在今日页次级行动入口、Watch 在轻记录／更多入口提供“开始工作间歇”。默认 60 分钟，可选 30／45／60／90／120 分钟，记住用户上次选择。首次说明这是定时提醒，不代表设备持续确认人在坐着。

开始后保存 `DeskSession`：`id`、`originDeviceID`、`startedAt`、`dueAt`、`state`、`revision`、`notificationID`、`snoozeCount`。状态为 active、snoozed、due、completed、cancelled；到期和已活动是不同事实。

用 `UNTimeIntervalNotificationTrigger` 安排一次本地通知。已经安排的通知由系统负责呈现，不需要后台循环计时。页面退出以后保留计时事实，重启从持久化截止时间恢复；日期跳变需要重新核验剩余时间。[A7]

同一设备同时最多一条活动间歇。再次开始时先选择继续或替换，不静默叠加。初版不默认自动循环；活动完成后提供“再开始一段”，由用户明确点击。

### 10.3 到时交互

通知正文包含一条中性建议，例如“到了约定的活动间歇，可以轻松走动一会儿”。它只是开发占位文案，不写“检测到你已经连续坐了 60 分钟”。默认隐私模式不带健康数值。

注册 `FANGCUN_ACTIVITY_BREAK` 类别，按系统实际显示容量提供：开始 2 分钟活动、10 分钟后、今天不再提醒。通知点击本体进入活动准备页。开始行动需要前台与场景安全确认，不能在后台偷偷启动触感或音频。

“10 分钟后”先撤销当前待处理请求，再创建同一 DeskSession 的新 revision；每次明确操作只生成一个请求。最多连续延后 3 次，之后只提供结束这一段或重新手动安排。今天静音取消本机剩余活动提醒，标明只影响方寸。

用户选择“已经活动”记为自报完成，不写 Apple 站立分钟或自动补满圆环。活动提前结束保存实际时长，显示中性反馈。

### 10.4 可选固定时段

设置页允许额外开启“固定活动间歇”，默认关闭；开启后的初始建议为工作日 11:00、16:00，用户可以删除或修改，每天最多 2 个固定时点。属于普通日程提醒，无需健康或运动权限。

采用有界的未来 7 天单次请求，不依赖永久重复通知；每次有运行机会时补齐，展示“已安排至哪一天”。长期不打开而未获得后台机会时，排程可能停止，不能承诺永续精确执行。所有请求计入统一通知调度与去重。

修改时区、工作日、免打扰时间或今天静音后，只在本应用范围内取消和重排。不要在下一次运行时补发所有已经错过的提醒。

### 10.5 情境抑制及其局限

在应用有运行机会时，可根据本机正在进行的练习、明确开始的训练记录、用户今天静音等已知事实取消不合适的待发请求。**后台没有运行机会时，不能保证在通知送达前再次读取健康／运动状态。** 因而本版不承诺自动避免所有睡眠、驾驶或训练场景，默认只在用户约定的时间提醒，通知措辞保持中性。

权限拒绝后显示本机计时和开启通知入口，不显示“提醒已开启”。系统专注模式可能延后或静音通知；应用不绕过。跨越免打扰时段的一次手动计时，在开始时提示该到期时间不响铃，并允许用户调整。

过期通知被点开时先核对 DeskSession 状态；结束、取消、修订过或超过到期 2 小时的请求只进入当前页面，不自动开始旧行动。用户仍可主动开始一次新的轻活动。

### 10.6 M7 传感辅助，暂不成为首发依赖

只有 MVP 验收后才探索 Core Motion／步数／站立小时的辅助线索。按需申请权限，检查实际可用性、数据时间与设备在身情况；静止或零步数不足以证明久坐，缺数据不得当作零活动。

先做“应用打开时或获得合法后台机会时的辅助提示”。已有可靠活动证据可减少提示；没有证据不自动强化提示。不要通过连续位置、音频保活或伪训练获得定时运行，也不要承诺准确在第 50／60 分钟发现久坐。

只有在明确版本的 SDK 中找到官方公开接口并完成真机验证，才能提出新的系统事件接入变更；须记录文档、最低系统、回退和隐私影响，不能凭相似名称推测存在回调。

## 11. 统一提醒策略

### 11.1 三类提醒的默认政策

| 类型 | 开启方式 | 触发条件 | 限额 |
| --- | --- | --- | --- |
| 晨间恢复摘要 | 用户主动开启 | 新主睡眠评估成熟、有效、等待数据收敛后，在用户设定窗口获得执行机会 | 每周期最多 1 次，按本地日期最多 1 次 |
| 固定活动间歇 | 用户自行选择时点 | 到达约定时刻；不声称实时检测身体 | 每个日期最多 2 个时点 |
| 手动工作间歇 | 每次明确开始 | 本次定时到期或用户明确延后 | 同设备只保留 1 个有效请求，无默认自动循环 |

默认免打扰 21:30—08:00，可改；晨间窗口默认 08:00—11:00，轮班用户可选自定义。常规自动提醒每天总计最多 3 个请求，任意两个自动提醒至少间隔 60 分钟。手动启动的一次计时视为用户主动请求，不计入自动额度，但仍遵守静音选择；每天第 6 次手动计时后提示可以关闭提醒，不暗中禁止用户继续。

晨间提醒先检查当前资料状态为 assessable，且 freshness 为 current。provisional／limited／insufficient 只在应用内呈现，不主动推断健康状态。初版不再追加“准备度突然降低”的日间健康警报；相关策略留待模型校准。

没有合适后台机会、数据未到、已超出晨间窗口时跳过本次提醒，不在下午补发“早安”。可以在用户下次打开时看到已有评估。Observer 通知、后台任务与固定本地时间通知不可当作同一机制。

### 11.2 提醒调度对象

`ReminderCandidate` 至少包含 `id`、`kind`、`cycleID` 或 `deskSessionID`、`assessmentRevision`、`generatedAt`、`earliestAt`、`expiresAt`、`ownerDeviceID`、`priority`、`contentKey`、`actionIDs`、`dedupKey`。

`ReminderPolicyEngine.evaluate(candidate, preferences, ledger, now)` 返回 schedule、suppress 或 replace，以及稳定原因码。相同 `dedupKey` 无论数据重复到达几次，只保留一个有效请求。要记录 scheduled、cancelled、acted、expired 等可观察事实，不把 scheduled 当成用户已看见。

通知内容不在排程时使用未来可能失效的实时健康断言；晨间摘要带周期／日期含义，过期点击重新读取当前评估。应用无法保证在系统延后送达前再次执行代码，不能用一个后台 delegate 来承诺送达前检查。[A7]

### 11.3 跨端责任

普通自动提醒由 iPhone 安排一次，让系统按用户设置决定呈现在手机或 Watch。不要为了“确保腕上可见”，又独立在 Watch 安排同一通知。苹果的配对通知路由由锁定、连接与通知设置等条件决定，具体行为需使用本地通知真机验证。[A8]

在 Watch 明确开始的工作间歇由 Watch 安排本地通知，手机只接收会话事实，不重发。反向同理。跨端重复手动开启的离线会话可能短暂并存；恢复连接后提示用户选择保留，不能假装离线时有全局锁。

### 11.4 权限、隐私与负担

首次打开不请求通知。用户开启对应提醒时先说明用途，再调用系统授权。关闭某类提醒立即取消本机该类所有 pending 请求；重新开启不补发过期请求。

使用普通通知级别，不申请 Critical Alerts，不默认 Time Sensitive，不用徽章制造“未完成任务”。初始通知标题和正文不含 HRV、睡眠时长或恢复等级；用户可明确开启详细显示。

区分系统通知权限、应用类别开关、系统可能静音和本地排程结果。设置页可发一条由用户触发的测试提醒，不把测试成功等同未来每次必达。

用户只关闭横幅或未点开不能被推断为练习无效。只有明确反馈才能进入偏好统计。提醒统计留在本机，不加入遥测。

## 12. 主屏幕、锁屏、Watch 组件与实时活动

### 12.1 WidgetKit 规格

| 组件 kind | families | 核心信息与跳转 |
| --- | --- | --- |
| `FangcunReadinessWidget` | systemSmall、systemMedium | 状态／资料状态、评估时间；中尺寸增加一条依据和独立练习入口 |
| `FangcunLockWidget` | accessoryCircular、accessoryRectangular | 默认中性品牌入口；详细模式显示简短状态和时间，点击到依据 |
| `FangcunWatchWidget` | accessoryCircular、accessoryRectangular | 表盘与 Smart Stack 的状态摘要或常用练习入口 |

同一 Widget 可配置“查看恢复”或“开始常用练习”，使用明确配置选项，不随算法随机切换入口。圆形组件不画未经验证的分数环；使用状态符号、简短文字或品牌标记。没有资料时显示中性入口，不能用漂亮的平稳状态填充空白。

组件消费同一 `ReadinessSummaryDTO` 与用户偏好。每台设备在自己的 App Group 内保存最小摘要；不用共享完整 SwiftData 数据库，也不在 Widget 中运行健康查询、基线重算、长同步或音频。

### 12.2 时间线与过期

每次有效评估或偏好变更后发布原子快照，再请求 `WidgetCenter` 重载。时间线可以包含当前状态、到期后的中性状态；不能预测未来身体会恢复。

刷新时机由系统安排，请求时间不构成执行保证。[A5] 为迟到刷新设计保守回退，显示原评估时段；不要用 Widget 绘制时间替代测量时间。应用打开时主动核对并更新缓存。

占位、系统预览与实际 timeline 数据分开；预览数据必须标记为示例。相同 snapshot revision 在各入口显示相同语义。动态计时只展示系统支持的时间表达，不以重载 Widget 追踪秒级状态。

### 12.3 视觉与隐私

复用品牌字色、间距语义、确认原画的静态裁切；不在组件中运行动画 shader。支持 fullColor、accented、vibrant 等实际渲染模式，不强制纸白背景破坏系统小组件表现。Watch Smart Stack 使用系统要求的容器背景与相关性机制，不能保证永远置顶。[A6]

锁屏默认中性；详细健康内容须用户主动开启。为敏感视图设置系统隐私标记，并使共享快照遵守最小化与数据保护设置。锁定／首次解锁前读不到缓存时正常回退，不改成不受保护的完整健康存储。

关闭详细模式后清理相关缓存并重载组件；断连的手表可能需要收到偏好更新后才能同步改变，须明确待同步状态。隐私标记不能代替数据保护与清理。

### 12.4 统一深链接与 App Intents

集中定义 `FangcunRoute`，只允许 readiness、practice、recoveryAction、activityBreak、history、settings。URL 例如 `fangcun://readiness?cycleID=...`，仅传内部 ID，不携带生理数值、诊断文字或完整个人资料。

冷启动先完成容器与导航准备，再消费待处理路由；热启动不重复压入页面。外部传入的动作 ID、时长与枚举必须白名单校验。未知路由回今日并显示轻提示，不崩溃、不发起健康写入。

Widget、App Intent、通知动作共用动作处理器。对同一 `actionInvocationID` 去重，避免双击启动两个练习。已有练习运行时，先回到它，不能再启动一个计时器。用户从“开始”入口进入时可以直接启动其已配置且完成过安全说明的练习；首次仍执行准备流程。

锁屏可能需要解锁才能进入或操作；不能承诺一键越过设备安全限制。平台不支持的交互回退到深链接，勿为了一个按钮提高最低系统版本。

### 12.5 Live Activity：只服务已开始的手机练习

本版作为 M6 的独立小任务实施，不阻塞 Watch 与准备度主链路。复用 iOS Widget Extension 加入 ActivityKit 配置，支持锁屏和具备条件的 Dynamic Island；无 APNs 服务、无远程更新依赖。[A11]

属性保存 `sessionID` 和活动类型；内容状态保存 running／paused／ending、计划结束时间、已完成有效时长、展示文案 key、revision。只在用户已经主动开始练习后请求，系统不允许或用户关闭时仍能正常练习。

只显示剩余时间、暂停状态和返回正在进行的练习入口；v1 不实现锁屏上的逐秒吸气／呼气引导，不在扩展中运行练习主时钟。暂停与继续以应用会话控制器为权威，先保存事实，再更新 Live Activity。

同一手机最多一个方寸 Live Activity。完成、取消、保存失败以及崩溃后恢复均有清理逻辑；设置 staleDate，迟到内容变为中性。倒计时到了零不代表应用已经保存完成，也不能凭 Live Activity 的显示给练习补时。系统回收或不及时更新时，不影响主会话记录。

## 13. 代码组织、文案与工程配置

### 13.1 建议新增模块

以下是逻辑落点，Codex 应结合现有命名合并最小实现。不要为每一个 struct 建立多层抽象框架。

| 层 | 建议文件／目录 | 职责 |
| --- | --- | --- |
| Core | `Readiness/ReadinessModels.swift`、`ReadinessEngine.swift`、`ReadinessPolicy.swift` | 类型、确定性评估、版本化参数 |
| Core | `Readiness/MetricBaselineBuilder.swift`、`SleepCycleResolver.swift`、`DataQualityGate.swift` | 基线、周期识别、质量门控 |
| Core | `Recovery/RecoveryAction.swift`、`RecoveryRecommendationEngine.swift` | 轻活动与推荐，不依赖 UI |
| Core | `Reminders/ReminderPolicyEngine.swift`、`DeskSession.swift` | 提醒资格、时间与幂等逻辑 |
| Core | `Sync/SyncEnvelope.swift`、`ReadinessSummaryDTO.swift` | 跨端版本化协议，不导入 HealthKit |
| iPhone | `Health/HealthKitRepository.swift` 周边新增读取适配器 | 规范化输入、按类型增量读取、来源处理 |
| iPhone | `Features/Readiness/ReadinessCoordinator.swift` | 单次计算、刷新合并、发布结果 |
| iPhone | `Persistence/InsightsStore.swift` 与迁移器 | 评估、周期、事件、反馈与删除记录 |
| iPhone / Watch | `Connectivity/`、`Notifications/`、`Routing/` | 对应端传输、提醒与深链接适配器 |
| Watch | `Features/Today/WatchTodayView.swift`、`WatchSessionController.swift` | 首屏和独立练习会话 |
| 共享 UI | `DesignSystem/` 的轻量 Token 与静态资产 | 继承风格；扩展不依赖完整 App UI |
| 扩展 | iOS Widget Extension、Watch Widget Extension | 各端组件；ActivityKit 放 iOS 扩展 |

现有呼吸、音频、安全退出、完成保存、HealthKit 写入队列继续复用。拆分后旧测试与用户记录必须仍然可用。Core 保持 Foundation 为主，避免把 WatchKit／SwiftData／UserNotifications 全部塞入算法包。

### 13.2 Xcode 与签名

新增 target 和 App Group 前，记录现有 Bundle ID、部署版本、依赖关系与 entitlements。保持原 App 身份，不能通过换 Bundle ID 绕过迁移问题。Widget 的 Bundle ID 由既有 App ID 派生，具体值在项目配置中确定，不写死用户 Team ID。

同一端 App 与扩展配置同一合法 App Group；不同设备不共享物理容器。开发团队权限或 App Group 注册需要用户在本机确认时，记录准确阻塞，仍完成不依赖签名的 Core 与模拟器编译。不要索要或上传证书、令牌和设备标识。

按实际使用更新 HealthKit、后台交付、扩展运行、通知和用途描述。Privacy Manifest 中 Required Reason API 必须匹配真实使用及苹果允许的原因，Codex 应核对所用 SDK 与官方列表，不能随便填一个原因代码以通过检查。[A12]

### 13.3 文案集中管理

所有新增文字使用 String Catalog 和稳定语义 key；不把完整中文作为同步协议或状态枚举。`ReadinessLevel.low` 与用户最终改成什么标题无关。

交付 `COPY_REVIEW.csv`，列包含：key、模块、使用场景、中文初稿、参数、最大推荐行数、是否安全说明、待人工确认、备注。示例 key：`readiness.level.reduced.title`、`readiness.source.stale`、`watch.session.interrupted`、`activityBreak.suggestion.move`。

数字、时间、来源与句式使用格式化参数；不用字符串拼接硬凑中文。测试用 accessibilityIdentifier 和模型值，不依赖将来会被修改的整段文案。布局验收包含初稿长度翻倍、中文大字和英文较长来源名。

完整安全信息可以二级展开，但不能因为用户稍后改文案而留空。保留文案审阅状态，未审阅的安全相关内容不得在正式发布检查中标为完成。

### 13.4 功能开关与回退

按 readiness、watchToday、watchSessions、widgets、activityBreak、reminders、liveActivity 设置编译／内部功能开关，并明确依赖。关闭 readiness 后保留经过 M1 修复的旧状态链路；关闭通知不影响练习；关闭同步不删除本地事件；关闭 Live Activity 不改变时长记录。

不能把假分数或演示状态作为开关关闭后的默认。正式包不暴露调试注入入口。参数调整必须更新 policy version 与测试 fixtures，不能用远程配置偷偷改健康结论。

## 14. 分阶段任务单与依赖

### 14.1 阶段次序

实施主线为 `M0 → M1 → M2 → M3 → M4 → M5 → M6`。M7 为明确暂缓项。每阶段完成后更新任务状态和验证证据；单个设备能力受限时继续其他可验证任务，但不把相关功能标成已验收。

先做到一条真实链路可运行，再补全部入口。禁止同时重写健康仓库、存储、Watch 会话和视觉系统，导致无法定位回归。

### 14.3 每阶段退出条件

M1 后，旧界面语义正确且原有练习不回归。M2 后，用 fixtures 能完整重放评估；未依赖 Widget 或 Watch。M3 后，手机形成“真实数据→评估→建议→记录”的闭环，迁移成功。M4 后，Watch 能离线完成和保存，并有真机触感／后台记录。M5 后，通知与系统入口使用一致结果。M6 后，只把有实际证据的项目写成已通过。

M0-03 的 Watch 后台实验可与数据算法研究并行；不为等候一项能力而停止基础 Core 开发。无真机时 M4 的相应验收停留在“待真机”，不能以编译通过代替。

### 14.4 任务进度文件格式

`TASKS.md` 每条任务使用 `not_started / in_progress / implemented_unverified / verified / blocked`。每个 verified 必须指向命令输出、测试名、截图或真机记录。用户文案未最终审阅时可标功能完成，但内容发布审阅仍待完成。

`DECISIONS.md` 记录新增参数取舍与原因；`BLOCKED.md` 只写具体依赖、已尝试办法、下一步可执行动作，不写笼统“平台不支持”；`CAPABILITIES.md` 保存官方接口、SDK availability、实验步骤和真实结果。

### 15.6 有效性与试用门槛

工程正确与模型有帮助分开验收。本版首先作为个人恢复参考试用：邀请愿意提供反馈的成年人，在明确知情下记录一段真实使用，验证资料可获得性、结论理解、错误安慰、过多提醒、练习启动阻力和主观帮助。

可以先用 10–15 位、连续约两周作为可用性试运行规模；这不构成统计功效计算，也不能证明医学准确率。睡眠不足、运动后、旅行、夜间不佩戴、非 Watch 来源与轮班至少有代表场景。没有覆盖的群体如实列出。

提前定义参考观察与问题清单，避免看到数据后再挑有利结论。不以用户愿意打开 App 代替准备度有效性；不以 HRV 对算法的高相关证明算法正确，因为它本身就是输入。

外部公开任何准确率、预测能力或医学效果前，需要另行设计验证并审查证据。本次开发不能声称完成这项验证。安全说明、健康权限解释、非诊断表述以及新动作内容需人工审阅；文案可后改，但这些语义边界不得删除。
