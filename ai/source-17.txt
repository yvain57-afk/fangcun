===== FILE: docs/plans/fangcun-score-v3/DECISIONS.md =====
# V3 decisions

1. `fangcun-status-3.0` is a separate engine; old readiness models and golden fixtures are retained for legacy history/data safety. Numeric sleep/HRV/RHR features are independent of old assessable/provisional/limited gates.
2. Source initialization is per metric. Only a completed metric can choose its initial source and publish a score/cursor transaction. First valid sleep publishes before HRV starts. A subsequent query error cannot remove a previously valid component and silently reweight it.
3. RHR uses its own same-source local-date history. HRV preserves confirmed-asleep and intervention exclusions with 1-sample eligibility and progressive quality weight. Floating-point normalization is clamped to the declared closed range, with a regression for exactly 100, not a changed model parameter.
4. Snapshot fingerprints omit query/refresh clocks; include selected source segments, actual input/dependency changes, window policy and configuration. Goal changes revise the current cycle and leave prior snapshots intact. Optional schema-1 fields retain existing stores and deletion barriers. Manual sleep never writes to HealthKit and can calculate without authorization.
5. Sleep/wake coverage uses versioned sub-minute alignment (`status-quality-3.0-gap60`). Asleep-only and unresolved conflicts do not invent a continuity score. Regularity can be disabled by the user.
6. The current surface is numeric. Default details show only used components and actual normalized weights; method/diagnostics are explicit disclosure. New history separates versions and composition changes; no score is backfilled into legacy records.
7. Main action changes with night, safety, explicit context/preferences and negative feedback. Existing practice/quiet rest/seated reset routes save real records, with no score reward. Subjective feeling records remain visible separately from the numeric assessment.
8. Score-v3 is a minimal negotiated DTO. Legacy Watch receives readiness revocation, not a mapping from number to an old level. No Watch/Widget/Live Activity UI or new backend/permissions were added.
9. V3 explicitly authorizes replacement of obsolete homepage UI expectations. Four former test files are archived verbatim under `legacy-ui-contracts/`; current tests check numeric identity, records, feedback, scroll/hit targets and independent measurement/query/calculation times. Core/App legacy safety assertions and original fixtures are unchanged.
10. XCTest runs affected by host sleep are recorded as failed/invalid environment runs and rerun awake with process-scoped `caffeinate -i`. No permanent power preferences changed.

11. Covered home content is hidden from accessibility during a full-screen practice/action, preventing duplicate resume buttons. Post-practice coordinate choices reuse their exact existing choice names when displayed on home; no saved feeling is relabeled into a score.
12. Displayed HRV uses the same exp(log-median) representative as scoring. Explicitly selecting a HealthKit main-sleep episode supersedes an active manual override while preserving its historical snapshot. Both have raw/storage regressions.

13. Final maximum-type visual inspection found toolbar symbol/wordmark overlap. Brand artwork and toolbar symbols keep intrinsic 20-point drawing size and 44-point hit targets; score, reason and all page content continue to follow Dynamic Type. UI regression checks the actual brand/control frames for overlap.
