# 概念板生成与验收记录

## 生成方式与轮次

- 使用 Codex 内置 `image_gen`，输出为原创 2D 概念探索；第 3 轮只抽取用户参考图的高层画法，不复制其中角色、品种、花纹、配饰、姿势、文字或水印。
- 第 1 轮：A 首稿误生成人物，定向修订只替换该格；B/C 首稿结构通过。领导随后否决整体视觉，明确指出“第一眼不够可爱、颜色不够吸引”。
- 第 2 轮：A/B/C 均重做眼距、脸颊、口鼻、短爪与色块；仍被认为不够接近用户期待的手绘可爱风格。
- 第 3 轮：依据八张用户参考图，统一改为深棕变线宽、轻微手抖、扁平亮色、胖短低重心、大爪、短排线与动作小短线；A/B/C 骨架和全部验收模块保持。累计使用 **3/3** 轮，修订到此停止。
- 内置结果复制到本目录后，以 `sips -Z 2560` 统一长边；A/B 为 2560×1601，C 为 2560×1707。未制作 App 页面或正式上架资产。
- 概念轮封存后，用户明确要求按“缩眼、减腮红、固定非对称耳与色块、强化逗号尾和大爪”先试一次；因此新增 `concept-a-refined.png`（2560×1601）作为 **A 方向定型试验**，不计作第四套广度探索，也不覆盖 `concept-a.png`。生成工具未明确披露 GPT Image 2，故角色系统 Skill 只用于身份锁定清单，实际图片使用 Codex 内置 `image_gen`。

## A 方向定型试验（已否决）

用户明确否决“为了成年感而缩眼、减腮红”的处理，并指出单张综合板不足以证明角色系统。`concept-a-refined.png` 仅保留追溯，不得再作为身份或风格参考；以下提示词与观察均不再代表当前方向。

以 `concept-a.png` 为唯一身份与版式参考，重绘原创“焦橙猫＋蜜糖狗”：深可可变线宽、轻微手抖、干净扁平色，成年向且一眼可爱。猫固定为矮圆梨体、宽 W 奶油脸、焦橙头肩、右耳略内倾但双耳永远竖立、较小暖棕椭圆眼、大并爪和粗短逗号尾；狗固定为低长椭圆体、蜜糖黄身体、奶油口鼻胸腹、左侧青色前折耳、右侧蜜糖垂耳、左肩青色侧斑、大爪和钝弯尾。腮红减少 20%，禁用默认吐舌、闪光大眼、爱心、花朵、服装和配饰。板面保留正面与 3/4 全身、并排、猫爪轻搭狗爪、奶油/石墨双主题、猫狗各六表情和黑白剪影；所有视图严格锁定耳型、耳色、花纹与尾型。配色为焦橙 `#E96F3F`、蜜糖 `#E6A63B`、奶油 `#FFF0D2`、Logo 青 `#397B80`、深可可 `#432E2B`；禁止文字、水印、现有 IP 相似、明确猫狗品种、诊断暗示、App UI 与 Logo 重设计。

试验稿历史观察：猫耳、狗耳与肩斑在六表情中基本锁定，但缩眼、低腮红削弱了核心萌感；狗的全身仍偏直立，互动也更接近抱臂而非严格的“爪搭爪”。

## 最终提示词骨架

所有方向共用：成年苹果用户、原创 2D、极度可爱但不幼儿化；一猫一狗身份一致；四个单体全身角度、并排、自然互动、六列猫狗双头像表情、奶油/石墨双主题、黑白剪影；禁止文字、服装、人物、疾病或诊断暗示、现有 IP 相似、Logo 重设计、UI 页面、3D、写实与水印。

- **A 圆糯矢量：** 焦橙团子猫与蜜糖狗，奶油大脸大爪、不对称灰蓝块、轻靠互动；轮廓最简，手绘短线最少。
- **B 柔软绒感：** 灰蓝云团猫与陶红软垫狗，三瓣颊绒、超大前爪、紫羽尾、深青瓣耳；借肩与尾覆背，身体压缩最明显。
- **C 弧面共生：** 珊瑚梨弧猫与玉青拱体狗，墨青外展耳、点端丝尾、陶橙弧耳和钝端半环尾；尾端轻触并呼应暖上弧、青下弧与中央点，但不组成新 Logo。
