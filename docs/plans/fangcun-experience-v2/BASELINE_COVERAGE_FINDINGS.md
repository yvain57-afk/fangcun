# V2-02 基线覆盖追查（脱敏）

## 核验对象与边界

对本机已授权复制的 M3 真机 Insights 存储作只读回放。读取前核对原封包 checksum；没有修改原文件、HealthKit、游标、权限或个人记录。完整 `BaselineCoverageAudit.json` 和旧/新政策回放对比仅保存在本机私有诊断目录，不进入仓库。本报告不包含健康数值、逐日样本、来源/设备标识或评估 ID。

## 已确认根因

- 数据初始化已完成，原始记录覆盖多个日期。不能将“有效日很少”解释为用户只佩戴一天，或未经核验就让用户再等两周。
- 当前保存的稳定选源与原始记录相符，本次未发现来源不匹配是主要原因。
- 旧代码将 core/deep/rem 的阶段交叠和 awake/asleep 的真假睡眠冲突合并为 `conflictingSleep`；历史 `episode.flags.isEmpty` 进一步将这些整晚排除。只有阶段细分不一致的有效睡眠因此被误删出基线。
- 新政策只降级阶段细分，总时长使用睡着区间并集。对同一批原始记录回放后，HRV 和 RHR 的有效基线覆盖都增加，证实修复作用于实际遗漏，而不是改门槛凑结果。
- 当前夜的阶段交叠与不完整设备身份仅需内部诊断，不阻断可比较睡眠时长。

## 仍须保留的限制

部分历史确有同源 awake/asleep 交叠，且没有共享替换标识和版本依据足以自动消解；不能因为同源或记录较新，就猜测某条为正确记录。另有 HRV 稀疏的真实过滤。修正后仍不能将所有指标宣称达到成熟个人比较条件，7/14 日门槛保持不变。

`BaselineCoverageAudit.build(snapshot:now:calendar:configuration:interventions:)` 使用与评估相同的睡眠构建器、每日主睡眠选取、当前指标提取与历史过滤路径。逐指标、逐日输出初始化状态、原始/去重/选源覆盖、睡眠候选和选中记录、质量分类、纳入样本、小时覆盖、过滤原因和主排除分类。分类区分未读取、读取未完成、旧档初始化状态未知、原本缺失、未选源、来源不匹配、无睡眠候选、睡眠规则排除与指标规则排除。

该审计是本机诊断对象，不属于跨端同步、普通用户文案或公开验证附件。本轮没有新增网络发送或日志自动上传。
