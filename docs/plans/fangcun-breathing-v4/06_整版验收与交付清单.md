# 整版验收与交付清单

本轮只有一个完整发布候选。下面是同一版本的验收维度，不是分期发布计划。所有“目标/应当”都需要执行后证据；此开发包本身不代表App测试通过。

## A. 产品结构

| 编号 | 必须满足的验收 |
|---|---|
| H01 | 默认打开呼吸页，仅两个主Tab：呼吸/日常；设置从日常可达 |
| H02 | 首屏有明确功能标题、方法名、时长和开始按钮；不以状态分为主图 |
| H03 | 首次未授权健康数据、无Watch、无网络时，9项练习均可本地开始/完成/保存 |
| H04 | 首页无健康连接、同步失败、大分数、饮品记录卡；这些全部在日常有对应入口 |
| H05 | 9項完整可达，默认目录有NSDR/冥想/凯格尔；四种新增方法不只是一张卡 |
| H06 | 可选筛选不强制选择情绪，直接开始无需先记录心境 |
| H07 | 日常保留状态详情、7/28天历史、旧记录、手工睡眠、饮品编辑撤销、关怀、感受、轻行动、设置 |
| H08 | 既有通知/深链去新对应位置，不中断进行中会话；无死链接 |

## B. 方法与时钟

| 编号 | 必须满足的验收 |
|---|---|
| T01 | 生理性叹息保留3/2/7及1/5分钟；60秒为5个完整周期，300秒25个 |
| T02 | 节律保留4/6及3/5分钟；不另复制一个同4/6的新方法 |
| T03 | 均衡5/5与4/4准确；时长到180/300秒时不擅自凑整轮改目标时长 |
| T04 | 方块3/3/3/3，两种停留阶段身体保持对应姿态，暂停即解除屏息指令 |
| T05 | 交替鼻孔顺序为左吸、右呼、右吸、左呼；侧别序列左/右/右/左，不是左右左右 |
| T06 | 膈肌正式训练无固定吸呼倒计时；示范单独标明，无传感器测量暗示 |
| T07 | 冥想5/10分钟、NSDR10/20分钟、凯格尔3分钟全部保留并实际执行 |
| T08 | 凯格尔4收8放，3分钟15轮；呼吸始终自然，不把收紧编码成憋气 |
| T09 | 暂停/准备/示范不计时；恢复不重置已练时间、不补播积压口令、不强接停留中段 |
| T10 | 结束/崩溃/锁屏中断只保存真实活动时间；不按离开时间伪造完成 |
| T11 | 快速反复点开始、暂停、结束不会出现两会话、重复音频或重复记录 |

## C. 角色与美术

| 编号 | 必须满足的验收 |
|---|---|
| M01 | 九项有九套可辨识的专属场景，维持认可猫狗身份和轻版画风格 |
| M02 | 头/眼/爪/耳/尾/胸腹至少按场景需要独立表现，主循环不是整图放缩 |
| M03 | 脚底和支撑点稳定；无接缝裂开、重复手脚、漂移、纹理闪烁、遮挡错误 |
| M04 | 补吸小于主吸；停留静止；左右与口令一致；凯格尔无全身发力示范 |
| M05 | 坐到躺有真实姿势过渡，未通过旋转拉伸立绘代替 |
| M06 | 语音身体焦点与NSDR局部放松一致；冥想不变成视觉追逐游戏 |
| M07 | 暂停、退出、成功、失败、夜间有对应收束；先保存再确认成功 |
| M08 | standard/gentle/static、系统减少动态效果、大字号、深色均保持教学含义 |
| M09 | 首页只一个主场景活动；目录卡使用各自关键姿势，离屏不持续解码 |

| A06 | 耳机移除、电话打断、后台回前台、系统音频中断均有正确恢复，不突发敏感播报 |

## E. 数据、旧功能与权限

| 编号 | 必须满足的验收 |
|---|---|

## F. 构建与证据

先读取工程已有测试命令与可用scheme。已知可执行基础包括`swift test --package-path InnerBalanceCore`、V3参考规则测试及Xcode的InnerBalance/InnerBalance Watch App相关scheme，实际设备和环境由执行时读取。

新增单元测试覆盖9项目录、全部节拍相位边界、变速、自然/分段训练、暂停、持续时长、幂等和旧枚举解码。UI测试至少覆盖无健康首启、九项入口及执行、两页迁移、保存失败重试、动态字号和关键音频中断。

原UI断言中“状态分占首页”与新目标冲突的部分，应据新的产品契约明确迁移并写清原因；评分逻辑fixtures保持原值。禁止删断言、skip失败、放宽颜色/可访问性标准来获得绿灯。

内部可以使用注入时钟快速验证长流程，但不能用加速测试冒充真实20分钟锁屏播放。保留本轮已经通过且未受后续变更影响的证据，避免让用户重复做无意义测试；最终交付提交上跑必要完整回归。

最终目录至少包含：

- `REPORT.md`：最终HEAD、范围、完成/未完成项、阻塞及真实验证边界。
- `CHANGED_FILES.md`：逐文件说明及旧入口迁移表。
- `VERIFICATION.md`：命令、时间、退出码、结果包、实际通过/失败情况。
- `ASSET_MANIFEST.json`：各场景图层、源图、许可/生产来源、音频与hash，不夹带凭证。
- 原生截图：新首页/日常、九项方法、深色、大字号、无健康空态。
- 实际原生录像：九项关键动作、暂停/恢复/结束、NSDR锁屏路线、旧数据访问。
- 签名构建/安装记录：代码SHA、bundle ID、应用版本与构建号、归档、手机回读及启动对应关系。

只有上传成功不算安装成功；只有模拟器跑通不算真机后台验证。未验证的项目保留明确状态，不以“应该可以”写成完成。

## G. 用户整版体验的五个观察点

用户拿到同一完整版本后，先打开是否知道用途；九項是否都容易找到；随便选一項能否舒服地跟完；猫狗是否真正有角色动作且不抢练习；旧功能是否都能在日常找到。此时再讨论优势、劣势和后续删减，不能提前拿半个页面要求用户批准剩余范围。
